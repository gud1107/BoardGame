# 그림 전화기(갈틱폰) 제시어 생성기 개편 제안 — 검토본 (미구현)

> 상태: **미구현 검토 문서** (2026-09-29). 외부에서 받은 "LLM 버퍼 큐 + 문법 엔진" 제안을 실제 코드와 대조해 기록한다. 코드는 한 줄도 바꾸지 않았다.
> 대상 게임: `src/games/doodlePhone/` (id `doodle-phone`)

---

## 1. 제안 요약

**문제 인식:** 현재 제시어는 `[A]를 [B]한 [C]` 식의 짧은 고정 문구라 금방 질리고 문법 골격이 반복된다.

**제안한 해결책 (하이브리드 2단):**

| 환경 | 방식 | 제안 파일 |
|---|---|---|
| 온라인(프로덕션) | 서버 부팅 시 + 백그라운드에서 Gemini Flash를 호출해 "엉뚱하고 그리기 좋은 기승전결 문장" 15개씩 벌크 생성 → 메모리 큐에 10~30개 유지, `getPrompt()`로 0ms 인출. 큐가 비면 아래 문법 엔진으로 대체 | `server/ai/promptGeneratorService.ts` |
| 오프라인/키 없음 | 주체(이름·특성·목표) × 계기(원인) × 클라이맥스 행동 × 장소를 3가지 서사 틀 중 하나로 조립하는 "의미론적 문법 엔진" | `server/ai/grammarEngine.ts` |
| 연동 | 텍스트 턴 시간초과 시 fallback, 봇의 1턴 제시어를 `promptService.getPrompt()`로 교체(봇은 `setTimeout` 1.5~3초 딜레이) | `server/GarticGameRoom.ts` |

LLM 프롬프트 규칙: 단순 명사 나열 금지 / 구체적 동작·황당한 인과·반전·B급 밈 / 표정·자세·도구 같은 시각 디테일 / JSON 문자열 배열만 출력, `temperature: 1.1`.

**기대 효과(제안 측 주장):** 문법 클리셰 탈피, 감정·상황 맥락이 뚜렷해 다음 사람이 그릴 디테일이 풍부해짐.

## 3. 제안과 실제의 충돌 지점

### 3.1 전제 불일치 — 서버 룸 클래스가 없다
제안은 `server/GarticGameRoom.ts`가 턴과 봇을 관리하는 권위 서버 구조를 가정한다. 실제로는 각 클라이언트가 같은 리듀서를 돌리는 락스텝 구조이고, 봇 행동도 `bot.ts`의 순수 함수(`rng` 주입)다. 연동부 코드는 그대로 붙일 곳이 없다.

### 3.2 락스텝 결정론 위반 (가장 치명적)
- 시간초과 fallback은 **모든 클라이언트가 각자 계산해도 같은 문구**여야 한다. 제안의 `promptPool.pop()`은 호출하는 쪽마다 다른 값을 돌려주는 가변 상태라, 두 클라이언트가 서로 다른 제시어를 앨범에 넣게 된다 → 앨범 불일치(디싱크).
- 문법 엔진이 `Math.random()`을 쓴다. 이 프로젝트의 리듀서·봇은 `seededRng`만 써야 한다(망각의 광산에서 같은 실수로 디싱크 발생한 전례).
- 봇 `setTimeout` 딜레이도 리듀서/봇 계약 밖의 부수효과다. 봇 타이밍은 이미 기존 봇 계약이 다룬다.

### 3.3 Vercel 서버리스와 "메모리 큐"
"서버 부팅 시 `init()`" / 프로세스 메모리 큐는 상주 서버를 전제한다. Vercel 함수는 인스턴스가 수시로 생기고 사라지며 인스턴스끼리 메모리를 공유하지 않는다 → 콜드스타트마다 큐가 비어 있고, 결국 대부분 문법 엔진 fallback으로 떨어진다. 로컬 JSON 통계 저장이 Vercel에서 휘발되는 것과 같은 계열 문제([analytics-local-store-limitations.md](./analytics-local-store-limitations.md)).

### 3.4 35자 제한 초과
제안의 예시·생성 결과 대부분이 `TEXT_MAX_CHARS = 35`를 넘는다.

| 글자 수 | 문장 | 출처 |
|---:|---|---|
| 47 | 만원 엘리베이터 구석에서 바지가 터진 줄도 모르고 눈물의 문워크를 선보이는 신입 사원 | "결과 예시" |
| 54 | 정막이 흐르는 독서실 한가운데에서 … 상담하고 있는 초능력자 중학생 | "결과 예시" |
| 37 | 치킨 배달원이 엘리베이터 거울 보며 춤추다 CCTV와 눈마주친 순간 | LLM 좋은 예시 |
| 36 | 다이어트 선언 1시간 만에 불닭볶음면 몰래 먹다 들킨 헬스트레이너 | LLM 좋은 예시 |
| 32 | 목욕탕에서 미끄러져 공중 3회전 후 온탕에 착지한 할아버지 | LLM 좋은 예시 ✅ |
| 27 | 정전된 노래방에서 생목으로 락스피릿 뽐내는 회사원 | LLM 좋은 예시 ✅ |
| 63~94 | 문법 엔진 실제 출력(case 0/1/2) | 코드 실행 |

엔진 fallback은 `isValidText`를 거치지 않고 바로 주입되므로, 길이 검증 없이 붙이면 사람은 쓸 수 없는 길이의 문장이 앨범에 들어간다. 봇 쪽은 `isValidText` 실패 시 `randomPhrase()`로 떨어져 새 문장이 아예 안 쓰일 수도 있다.

### 3.5 문법 엔진 출력 자체의 결함
- **case 2 비문:** `${action}하는` 조합 → "…빗물로 건배를 외친다**하는** 시골 똥강아지". `CLIMAX_ACTIONS`가 종결형(`~한다`)이라 관형형 접미사와 충돌.
- **case 2 장소 중복:** "미끄럼틀 위에서 비장하게 편의점 파라솔 아래에서…" — 장소 풀과 행동 풀 둘 다 장소를 포함.
- **조사 처리:** `이(가)`를 그대로 출력("똥강아지이(가)"). 받침 판별로 이/가를 골라야 한다.
- **결과 예시 과장:** "상담하고 **있는** 초능력자 중학생"은 코드가 만들 수 없는 형태이고, "다이어트 선언… 헬스트레이너"는 문법 엔진이 아니라 LLM 프롬프트의 예시 문장이다.
- 오타: "정막" → "적막".
- 조합 수: 6×7×6×5×3 ≈ 3,780가지지만 풀 크기가 작아 같은 조각("불닭볶음면", "문워크")이 몇 판 만에 반복된다 — 제안이 비판한 "금방 질림"이 조각 단위로 재발.

### 3.6 봇 체인 생존성
`BOT_OPENING_PROMPTS`는 봇 화가가 그릴 수 있는 단어 위주로 일부러 짧게 골랐다. "CCTV와 눈마주친 순간" 같은 문장은 봇이 그릴 템플릿이 없어 봇만 있는 체인이 1턴 만에 무너진다.

### 3.7 비용·운영
- Gemini API 키·과금·호출량 제한 관리가 새로 생긴다. 현재 프로젝트는 외부 유료 API 의존이 0.
- LLM 출력은 검수 없이 바로 게임에 노출 → 부적절한 문장 필터링 정책이 필요.
- `temperature: 1.1` + JSON 강제는 파싱 실패율이 올라갈 수 있음(제안 코드는 실패 시 조용히 스킵만 함).

## 4. 이 구조에 맞춘다면 (권장 방향, 결정 대기)

제안의 **목표(더 웃기고 그리기 좋은 서사형 제시어)** 는 타당하다. 구조만 이 프로젝트에 맞게 바꾸면 된다.

1. **1단계 — 정적 풀 확장 (가장 싸고 안전)**
   `prompts.ts`에 "상황+동작+표정"형 문장을 35자 이내로 수십~수백 개 추가. 제안의 LLM 예시 중 35자 이내 문장(목욕탕 할아버지, 정전된 노래방 회사원)이 좋은 톤 샘플. LLM은 **개발 시점에** 초안 생성 도구로만 쓰고 사람이 검수해 커밋 → 런타임 API 의존 0, 결정론 유지. 테스트에 `FALLBACK_PROMPTS` 전부 `isValidText` 통과 검사를 추가.

2. **2단계 — 문법 엔진 (원하면)**
   `prompts.ts` 옆에 `rng`를 인자로 받는 순수 함수로 구현(`Math.random` 금지), `fallbackPrompt()`의 `seededRng`를 그대로 넘김. 조각을 관형형으로 통일하고 받침 판별 조사, 길이 초과 시 재추첨/짧은 틀로 강등. 봇 오프닝에는 쓰지 않거나 "봇이 그릴 수 있는 명사"를 반드시 포함하는 틀만 사용.

3. **3단계 — 런타임 LLM (필요성 재확인 후)**
   필요하다면 Next.js API 라우트(`src/app/api/...`)에서 생성하고, **방장 1명만** 받아서 방 시작 시 `seed`와 함께 제시어 묶음을 브로드캐스트/상태에 넣어야 락스텝이 유지된다. 호출 실패 시 1·2단계로 fallback. 비용·키·콘텐츠 필터 정책 결정 필요.

**결정 대기 항목:** (a) 1단계만으로 충분한지, (b) 문법 엔진까지 갈지, (c) 런타임 LLM과 그 비용을 감수할지.
