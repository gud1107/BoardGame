# AI / 외부 연동

## 결론: 이 프로젝트에는 AI/LLM 연동이 없다

`package.json`의 의존성(`@supabase/supabase-js`, `idb`, `next`, `react`, `react-dom`, `uuid`, `zustand`)과 전체 소스 어디에도 OpenAI/Anthropic/Google Generative AI 등 LLM SDK, 임베딩 API, 벡터 검색, 프롬프트 템플릿 파일이 존재하지 않는다. 게임 규칙 판정(`engine.ts`)과 플레이어 식별(`src/lib/identity/resolve.ts`)이 "지능적으로" 보일 수 있는 로직을 담당하지만, 둘 다 **결정론적 순수 함수 / 규칙 기반 휴리스틱**이며 모델 추론을 거치지 않는다.

이 문서는 "AI 연동 문서가 빠진 게 아니라, 확인 후 의도적으로 해당 사항이 없다고 기록한 것"임을 남기기 위해 존재한다 — 다음 세션이 이 파일을 보고 "아직 안 썼구나"가 아니라 "이미 검토했고 없다"로 읽도록 하기 위함이다.

## AI로 오인하기 쉬운 로직들 (참고용 경계 표시)

- **플레이어 식별 매칭(`resolvePlayerIdentity`)**: 닉네임/기기ID/IP 이력을 조합해 "혹시 같은 사람 아닌지" 후보를 제시하지만, 최종 판단은 항상 규칙 기반 매칭(정확한 문자열 일치, 최근 접속 이력)이고 사용자 확인을 거친다. 퍼지 매칭(edit distance 등)이나 모델 추론은 전혀 쓰지 않는다. 자세한 내용은 [features.md](./features.md#플레이어-식별) 참고.
- **그리드 포커의 `evaluateHand`(포커 족보 평가)**: 브루트포스 탐색으로 모든 조커 배정 경우의 수를 전수 조사해 최고 족보를 계산하는 순수 알고리즘이지 학습된 모델이 아니다.
- **게임 엔진의 랜덤 요소(카드 셔플, 역할 배정)**: `seededRng`(mulberry32) 결정론적 PRNG를 쓴다 — "AI가 셔플한다"가 아니라 시드 하나로 두 클라이언트가 같은 순서를 재현하기 위한 장치([cloud-sync.md](./cloud-sync.md) 참고).

## 앞으로 AI 연동이 생긴다면 고려할 지점 (미적용, 참고용 메모)

현재 요구사항엔 없지만, 향후 논의가 나올 법한 지점을 짚어만 둔다:

- **룰북 질의응답**: `boardGameRule/*.md`를 컨텍스트로 준 RAG 기반 룰 설명 챗봇 등을 붙인다면, 토큰 예산·모델 선택·프롬프트 인젝션 방어(룰북은 신뢰 가능한 고정 텍스트라 위험은 낮음)를 이 문서에 추가로 기록해야 한다.
- **개인정보**: 이 앱이 다루는 개인정보는 닉네임과 IP 주소뿐이다(§ [architecture.md 3.1](./architecture.md#31-indexeddb-스키마-boardgame-db-v1--srclibdbclientts)). AI 연동을 붙일 경우 이 데이터를 외부 모델 API로 보내지 않는 것을 기본값으로 삼을 것 — 현재는 애초에 전송할 AI 연동 자체가 없으므로 이 문제가 발생하지 않는다.
