## 0. 한 줄 요약

**"상점 단계는 각자 동시에, 전투는 시드 하나로 모든 기기가 똑같이 계산한다."**
오토배틀러는 전투가 *플레이어 입력 없이* 진행되므로, 이 프로젝트의 락스텝 구조(순수 리듀서 + 시드 결정론)와 궁합이 아주 좋다. 전투 결과를 네트워크로 보낼 필요가 없다 — 각 클라이언트가 같은 시드로 같은 전투를 재생한다.

| 요소 | 하스스톤 전장 | 롤토체스(TFT) | 이 게임의 선택 | 이유 |
|---|---|---|---|---|
| 보드 형태 | 1줄 7칸 | 육각 4×7 배치 | **1줄 7칸** (v2에서 2줄 앞/뒤열 검토) | 모바일 세로 화면에 그대로 맞음, 전투 시뮬이 단순·결정론 검증 쉬움 |
| 전투 방식 | 왼쪽부터 번갈아 1회씩 공격 | 실시간 이동·사거리·마나 | **턴제 교대 공격(전장식)** | 실시간 물리 없음 → 락스텝 유지, 호스트 권위 예외 불필요 |
| 상점 | 개인 상점, 여관 등급업 | 공용 풀, 레벨=확률 | **여관 등급(1~6) + 공용 풀** | 등급업 결정의 긴장감 + 공용 풀의 "남이 가져간 유닛" 견제 |

| 시너지 | 종족 키워드(약함) | 특성 2/4/6 단계 보너스 | **종족 + 단계형 시너지(2/4/6)** | 롤토체스 쪽이 덱 방향성이 뚜렷해서 초보자도 목표가 보임 |
| 경제 | 매 턴 골드 +1 (최대 10) | 이자·연승/연패 보너스 | **전장식 고정 증가 + 연승/연패 보너스(이자 없음)** | 이자는 계산 부담이 커 캐주얼 플랫폼에 과함 |
| 영웅 | 영웅 능력 | 없음(증강) | **영웅 6~8종 (게임 시작 시 2택 1)** | 리플레이성 확보, 밸런싱 범위는 작게 |
| 아이템 | 없음(일부 시즌 장신구) | 아이템 조합 | **v1 제외** | UI·밸런스 비용 대비 효과가 낮음, v2 후보 |
| 체력 | 영웅 HP 30~40 | 플레이어 HP 100 | **HP 30, 패배 시 `여관 등급 + 살아남은 적 유닛 등급 합` 피해** | 전장식 공식이 직관적 |

**저작권 주의**: 하스스톤/TFT의 이름·카드명·일러스트·고유 효과 문구를 쓰지 않는다(라스베가스 실제 카지노 사진 교체 건과 같은 원칙). 메커니즘은 장르 공용이지만 유닛 이름·종족·아트는 전부 오리지널.

## 2. 게임 규칙 (v1)

### 2.1 기본

- 인원 **2~8명** (권장 4~8), 봇으로 빈자리 채움 — 혼자서도 7봇과 즉시 플레이.
- 각 플레이어 HP 30. 0이 되면 탈락, **최후의 1인 승리**, 순위 = 탈락 역순(자동 순위 `supportsAutoRanking: true`).
- 라운드 = **상점 단계(동시) → 전투 단계(자동) → 결과**.

### 2.2 상점 단계 (제한시간 30초, 라운드가 지날수록 +5초, 최대 60초)

| 행동 | 비용 | 비고 |
|---|---|---|
| 유닛 구매 | 3골드 | 손패(최대 10)로 들어감 |
| 유닛 판매 | +1골드 | 유닛은 공용 풀로 반환 |
| 새로고침 | 1골드 | 상점 유닛 전부 교체 |
| 상점 고정(🔒) | 무료 | 다음 라운드에도 같은 상점 유지 |
| 여관 등급업 | 5→7→8→9→10 (매 라운드 1씩 할인) | 상점 칸 수 3→4→4→5→5→6 |
| 배치/순서 변경 | 무료 | 보드 7칸, 순서가 곧 공격 순서 |
| 영웅 능력 | 영웅별 0~2골드 | 라운드당 1회 |

- 골드: 1라운드 3, 매 라운드 +1, 최대 10. 연승/연패 3회 이상이면 +1.
- 모든 플레이어가 **준비 완료**를 누르거나 시간이 끝나면 전투 시작.

### 2.3 전투 단계 (완전 자동)

1. 매칭: 살아있는 플레이어끼리 1:1. 홀수면 한 명은 직전 탈락자의 "유령 보드"와 대결. 같은 상대와 연속 대결은 피함(최근 2명 회피, 시드 기반).
2. 선공: 유닛 수가 많은 쪽, 같으면 시드로 결정.
3. 진행: 양쪽 **가장 왼쪽의 아직 공격 안 한 유닛**이 번갈아 공격. 대상은 상대 유닛 중 무작위(도발 유닛 우선).
4. 공격 = 서로 공격력만큼 피해 교환. 키워드(아래) 발동.
5. 한쪽 보드가 비면 종료. 승자는 패자에게 피해: `승자 여관 등급 + 살아남은 승자 유닛들의 등급 합`.
6. 무승부면 피해 없음. 전투 최대 200행동에서 강제 무승부(무한루프 방지).

### 2.4 키워드 (v1은 8개로 제한)

| 키워드 | 효과 |
|---|---|
| 도발 | 상대는 도발 유닛을 우선 공격 |
| 보호막 | 첫 피해 1회 무효 |
| 독 | 피해를 준 유닛 즉사 |
| 부활 | 죽으면 체력 1로 1회 부활 |
| 전투의 함성 | 구매(손→보드 배치) 시 1회 효과 |
| 죽음의 메아리 | 죽을 때 효과(소환/버프) |
| 광역 | 공격 시 대상 양옆에도 피해 |
| 성장 | 매 상점 단계 시작 시 +1/+1 |

### 2.5 종족·시너지 (6종족 예시)

| 종족 | 2명 | 4명 | 6명 |
|---|---|---|---|
| 🛡 기사단 | 기사단 보호막 1회 | 전원 보호막 | 보호막 깨지면 +2공격 |
| 🐺 야수 | 죽음의 메아리 소환체 +1/+1 | +2/+2 | 소환체 2배 |
| ⚙ 기계 | 판매 시 +1골드 | 기계가 죽으면 옆 기계 +2공격 | 첫 기계 부활 |
| 🔥 원소 | 새로고침 1회 무료 | 상점 원소 +1/+1 | 원소 구매 시 원소 1장 추가 |
| 💀 망령 | 첫 죽음의 메아리 2회 발동 | 아군 사망 시 망령 +1공격 | 망령 전원 부활 |
| 🐉 용족 | 전투 시작 시 용 +2/+2 | 용이 공격할 때 아군 +1공격 | 용 공격 2회 |

### 2.6 유닛 풀

- **등급 1~6, 종족당 등급별 2종 ≈ 6종족 × 12 = 72종 (v1 목표는 40종부터)**.
- 공용 풀 수량: 등급 1:16장 / 2:15 / 3:13 / 4:11 / 5:9 / 6:7 (8인 기준, 인원 적으면 축소).
- 상점 등장 확률: 여관 등급 이하 유닛만, 풀 남은 수량에 비례.

### 2.7 3장 합성(황금)

- 같은 유닛 3장 보유(손+보드) 즉시 **황금 유닛**: 스탯 2배, 효과 2배.
- 보상: **"발견"** — 내 여관 등급 +1 등급 유닛 3장 중 1장을 공짜로 획득.

### 3.2 핵심 아이디어: 전투는 네트워크로 보내지 않는다

```
상점 단계 (동시, 각자 자기 것만 수정)
  각 클라이언트 → game-action { buy / sell / reroll / move / levelUp / ready }
          ↓ 모든 기기가 같은 액션 시퀀스를 applyAction
호스트 → game-action { startCombat }      ← 단일 쓰기자 (그리드 포커 draw-common 패턴)
          ↓
각 기기: simulateCombat(보드A, 보드B, hash(seed, round, pairIdx))  → 같은 CombatLog
          ↓
CombatReplay가 로그 애니메이션 재생 → 결과(HP 감소)는 엔진이 즉시 반영
```

- `simulateCombat`은 **순수 함수**: 같은 입력 → 같은 로그. 엔진은 `startCombat` 액션에서 전투를 즉시 끝까지 계산해 HP를 확정하고, `CombatLog`는 UI 재생용으로만 state에 담는다.
- 애니메이션 길이(최대 ~25초)는 UI만의 문제. 재접속 클라이언트는 `state-sync`로 이미 확정된 상태를 받으므로 전투를 다시 돌릴 필요 없음.

### 3.3 동시 행동과 공용 풀의 충돌 문제 ⚠️

락스텝에서 "각 기기가 액션을 받은 순서"가 다를 수 있다. 상점 행동이 **자기 상태만** 바꾸면 순서 무관(Doodle Phone의 동시 제출 리듀서와 같은 원리)이지만, **공용 풀은 모두가 공유**하므로 순서가 결과를 바꾼다(마지막 1장을 두 명이 동시에 사는 경우).

**해결: "라운드 스냅샷 풀" 방식**
1. 라운드 시작 시 공용 풀을 스냅샷 `poolAtRoundStart`로 고정.
2. 각 플레이어 상점 굴림은 `seededRng(hash(seed, round, seat, rerollCount))` + `poolAtRoundStart − 내가 이번 라운드에 산 것`으로만 계산 → **남의 행동에 영향받지 않음 = 순서 무관**.
3. 판매·구매에 따른 풀 변화는 각자 `pendingPoolDelta[seat]`에 적립, 호스트의 `startCombat` 시점에 한꺼번에 합산.
4. 부작용: 같은 라운드에 두 명이 같은 마지막 1장을 둘 다 살 수 있음 → 풀이 음수가 되면 0으로 고정(허용되는 사소한 오차). 엔진 테스트로 "액션 순서를 섞어도 최종 상태가 같다"를 검증.

### 3.4 상태 모델 (요약)

```ts
type Phase = "heroPick" | "shop" | "combat" | "ended";

interface UnitInstance {
  uid: string;          // 결정론적 id: `${round}-${seat}-${counter}`
  defId: string;        // units.ts 키
  atk: number; hp: number;
  golden: boolean;
  keywords: Keyword[];  // 기본 + 획득 버프
}

interface PlayerState {
  heroId: string; hp: number; alive: boolean; placement: number | null;
  gold: number; tavernTier: number; upgradeCost: number;
  shop: (string | null)[]; frozen: boolean; rerollCount: number;
  hand: UnitInstance[]; board: UnitInstance[];  // board.length ≤ 7
  ready: boolean; streak: number;
  pendingPoolDelta: Record<string, number>;
}

interface State {
  seed: number; round: number; phase: Phase;
  players: PlayerState[];
  poolAtRoundStart: Record<string, number>;
  pairings: [number, number | "ghost"][];
  lastCombats: CombatLog[];       // UI 재생용
  shopDeadlineMs: number | null;  // 시간은 액션에 실어 전달 (Date.now 금지)
}
```

- 파생 상태 금지: 시너지 단계·보드 공격력 합 등은 **저장하지 않고 매번 계산**(docs/architecture.md §1.4).
- 타이머: 호스트가 마감 시각을 액션에 실어 보내고, 마감 시 호스트가 `startCombat`을 보냄(늦게 온 액션은 phase 가드로 무시).

### 3.5 봇 (ARCHITECTURE.md §7 필수 계약)

- `getValidMoves(state, seat)`: 상점 단계의 합법 액션 열거(구매 가능 / 판매 / 새로고침 / 등급업 / 준비).
- `chooseBotAction`: 휴리스틱 점수 — 레벨 1~10.
  - 낮은 레벨: 싼 거 사고 준비.
  - 중간: 시너지 종족 우선 구매, 3장 근접 유닛 우선, 4·6라운드 등급업 곡선.
  - 높은 레벨: 다음 상대 보드(공개 정보: 지난 전투에서 본 보드)에 대한 `simulateCombat` 몬테카를로 몇 판으로 배치 순서 최적화.
- 정보 공정성: 봇은 남의 손패·상점을 읽지 않는다. 상대 보드는 "마지막으로 전투에서 본 모습"만 사용.
- 상점 단계는 동시 진행이므로, 봇은 한 행동씩 0.5~1.5초 간격으로 내다가 `ready`로 끝냄.

```
├──────────────────────────────┤
│ 손패  [  ][  ][  ] …          │  ← 드래그해서 보드에 배치
├──────────────────────────────┤
│ 다른 플레이어 HP 순위 (가로 스크롤) │
│              [ 준비 완료 ✔ ]  │
└──────────────────────────────┘
```

- 드래그 대신 **탭-탭**(유닛 탭 → 칸 탭)도 지원 — 모바일 정확도 문제 회피.
- 유닛 카드: 공격력(좌하)·체력(우하)·등급 별·종족 아이콘·키워드 아이콘. 길게 누르면 상세.
- 판매: 유닛을 상점 영역으로 드래그 또는 상세창의 판매 버튼.

### 4.2 데스크톱

- 좌: 순위표(전 플레이어 HP·영웅·최근 승패) / 중앙: 상점+보드+손패 / 우: 시너지 상세·다음 상대 미리보기.

### 4.3 전투 연출

- 상대 보드가 위에서 내려와 위/아래 대치. 공격 유닛이 대상에게 돌진 → 피해 숫자 팝업 → 사망 시 파편.
- 2배속/건너뛰기 버튼(로컬 표시만 바뀌므로 동기화 영향 없음).
- 다른 사람 전투 관전 탭(내 전투가 먼저 끝났을 때).

## 5. 밸런스 방법론

1. **수치 설계 기준선**: 등급 N 유닛의 공+체 합 ≈ `4 + 3N` (키워드 하나당 −2~3 환산).
2. **봇 자가대전**: 8봇 × 수천 판 시뮬로 측정 —
   - 종족별 1위율 (목표: 모두 12~20%, 8인 기준 평균 12.5%)
   - 영웅별 평균 순위 (목표: 4.5 ± 0.4)
   - 평균 게임 길이 (목표: 12~16 라운드, 약 15~20분)
   - 시뮬 결과로 수치를 고치고, 고친 근거는 룰북/문서에 기록 (갓생 플래너 리튜닝 방식).
3. **전투 결정론 회귀 테스트**: 고정 시드·고정 보드의 CombatLog 스냅샷.

## 7. 결정이 필요한 항목

1. **보드 형태**: 1줄 7칸(권장) vs 육각 배치 — 육각을 고르면 전투가 실시간 이동이 되어 호스트 권위 동기화(지렁이 패턴)와 결정론 재설계가 필요, 공수 2~3배.
2. **인원**: 8인 풀방이 기본인가, 4인 빠른 모드(HP 20, 풀 축소)도 둘 것인가.
3. **세계관/아트**: 판타지 여관(기본안) vs 동물·과일 같은 캐주얼 테마.
4. **게임 시간**: 15~20분이 이 플랫폼 다른 게임보다 길다 — "빠른 모드(골드 시작 5, 라운드 타이머 20초)" 필요 여부.
