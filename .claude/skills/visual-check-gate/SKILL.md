# 시각 검증 범위 규율 (visual-check-gate)

## 진짜 문제

화면 하나는 사람이 보면 1초면 이상한지 아닌지 안다. 문제는 검증 자체의 비용이 아니라,
브라우저를 띄운 김에 "혹시 다른 것도 문제 있나" 하며 스크린샷을 더 찍고, 다른 화면/상태를
탐색하고, 재검증을 여러 라운드 반복하는 **범위 확장**이다. 토큰은 여기서 샌다.

(참고로 "작업 규모별 사용량 %를 추정해서 진행 여부를 물어보는" 접근은 시도했다가 폐기했다 —
근거 숫자가 미검증 추정치였고, 매번 되묻는 것 자체가 왕복 비용을 더했고, 무엇보다 진짜 낭비
원인인 범위 확장을 다루지 못했다.)

## 규칙

1. **스크린샷을 찍기 전에, 확인하려는 질문을 한 문장으로 먼저 정한다.**
   예: "수정한 버튼이 사이드바 버튼과 안 겹치는가?"

2. **그 질문에 답하는 데 필요한 최소 장수만 찍는다.** 거의 항상 1장. 전/후 비교가 꼭
   필요할 때만 2장. 그 이상은 이유 없이 찍지 않는다.

3. **질문에 답했으면 멈춘다.** 화면이 열려 있다고 관련 없는 다른 화면·다른 기능·다른
   플레이어 상태까지 스스로 둘러보며 "혹시 다른 버그도 있나" 탐색하지 않는다. 이건 사용자가
   명시적으로 요청했을 때만 한다.

4. **재검증은 실제로 코드를 수정했을 때, 같은 질문에 대해서만** 1회 추가로 한다.
   "혹시 몰라서" 여러 라운드를 도는 건 하지 않는다.

5. **로직/상태값만 바뀌고 화면에 영향이 없는 변경은 애초에 스크린샷을 찍지 않는다** —
   텍스트/로그/타입체크로 이미 충분하다.

## 요약

질문 하나 → 최소 스크린샷 → 정지. 그 이상의 탐색은 요청받았을 때만.
