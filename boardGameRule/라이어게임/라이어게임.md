# 라이어 게임 (Liar Game) — 완전 룰북 A to Z

> 한국에서 파티게임·예능으로 널리 알려진 "제시어 라이어 찾기" 게임의 룰북이다.
> 모두가 같은 **제시어**를 받지만, **라이어** 한 명만 제시어를 모른 채 **카테고리**만 안다.
> 시민은 제시어를 들키지 않게 설명하며 라이어를 찾아내고, 라이어는 정체를 숨긴 채 제시어를 알아내야 한다.
>
> 이 문서는 ① 오프라인 기본 규칙, ② 모든 예외·분쟁 상황 판정, ③ 변형 규칙, ④ 점수 규칙, ⑤ 온라인(앱) 구현 명세까지 한 번에 담는다.
> 일본 만화 『라이어 게임』(카이타니 시노부)의 개별 게임들과는 **다른 게임**이다.
> 앱에 넣을 경우 프로젝트 방침(`저작권, 상표권.md`)에 따라 표시명은 오리지널로 두는 것을 권장한다(예: "거짓말쟁이를 찾아라").

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 정체 숨기기 · 추리 · 말하기 파티게임 |
| 인원 | **3 ~ 10명** (권장 5 ~ 8명). 3명은 변형 규칙 권장(§15) |
| 시간 | 라운드당 5 ~ 10분, 한 판(여러 라운드) 20 ~ 40분 |
| 진영 | **시민**(제시어를 앎) vs **라이어**(카테고리만 앎) |
| 시민 승리 | 라이어를 지목하고, 라이어가 제시어를 **맞히지 못함** |
| 라이어 승리 | ① 지목을 피함, 또는 ② 지목당했지만 제시어를 **맞힘** |
| 진행자 | 오프라인은 진행자(사회자) 1명이 있으면 편하다. 없으면 카드/앱으로 대체 |

핵심 긴장: 시민은 **라이어에게 힌트를 주지 않을 만큼 모호하게**, 그러면서도 **동료 시민에게 "나는 안다"를 증명할 만큼 구체적으로** 설명해야 한다.

## 2. 구성물

오프라인 기준. 전용 구성물이 없어도 종이·휴대폰으로 진행할 수 있다.

| 구성물 | 수량 | 용도 |
|---|---|---|
| 제시어 카드 | 인원 − 1장 (같은 단어) | 시민에게 배부 |
| 라이어 카드 | 1장 | "당신은 라이어입니다" + 카테고리만 적힘 |
| 카테고리·제시어 목록 | 1부 | 진행자용 (§17) |
| 투표 도구 | 인원수 | 손가락 지목, 투표 용지, 또는 번호 카드 |
| 점수표 · 필기구 | 1 | 여러 라운드 진행 시 |
| 타이머 | 1 | 설명·토론 시간 관리 (휴대폰 가능) |

**진행자 없이 카드 만드는 법**: 같은 크기 종이 N장을 준비해 N−1장에 제시어, 1장에 "라이어"를 쓰고 접어 섞는다. 이때 카드를 만든 사람은 제시어를 알게 되므로 그 라운드에서 빠지거나, 앱/제시어 생성기를 쓴다.

## 3. 용어 정리

| 용어 | 뜻 |
|---|---|
| **카테고리** | 제시어가 속한 분류. 모든 플레이어(라이어 포함)에게 공개된다. 예: "음식" |
| **제시어** | 시민만 아는 정답 단어. 예: "김치찌개" |
| **시민** | 제시어를 받은 플레이어 |
| **라이어** | 제시어를 모르는 플레이어. 기본 1명 |
| **설명** | 자기 차례에 제시어에 대해 말하는 한 마디(한 문장) |
| **선 플레이어** | 그 라운드에 가장 먼저 설명하는 사람 |
| **지목/투표** | 라이어라고 의심되는 사람을 고르는 행위 |
| **최다 득표자** | 투표에서 가장 많은 표를 받은 사람 |
| **최후 변론** | 최다 득표자가 처형(공개) 직전에 하는 짧은 발언 (선택 규칙) |
| **정답 맞히기** | 정체가 드러난 라이어가 제시어를 한 번 말해보는 마지막 기회 |
| **바퀴(라운드 내 회차)** | 모든 생존 플레이어가 설명을 한 번씩 하는 단위 |

## 4. 게임 준비

1. **진행 방식 결정**: 라운드 수(보통 인원수만큼 또는 5라운드), 설명 바퀴 수(기본 1바퀴, 권장 2바퀴), 시간 제한, 사용 모드(§14)를 정한다.
2. **카테고리 선택**: 진행자가 카테고리 하나를 정하고 **모두에게 소리 내어 공개**한다.
3. **제시어 선택**: 진행자가 그 카테고리에서 제시어를 하나 고른다(무작위 권장).
4. **역할 배부**: 카드를 섞어 한 장씩 나눠준다. 각자 **혼자만** 확인하고 엎어둔다.
   - 시민 카드: 카테고리 + 제시어
   - 라이어 카드: 카테고리 + "당신은 라이어입니다"
5. **선 플레이어 결정**: 무작위(주사위, 앱), 또는 직전 라운드 선의 왼쪽 사람. 설명 순서는 **시계 방향**.
6. 확인이 끝나면 카드는 라운드가 끝날 때까지 **누구에게도 보여주지 않는다**.

> 진행자도 플레이어로 참여하려면 제시어를 몰라야 하므로, 반드시 카드 무작위 배부나 앱을 사용한다.

## 5. 한 라운드의 흐름

```
[준비] 카테고리 공개 → 역할 카드 배부
   │
   ▼
[설명] 선 플레이어부터 시계 방향으로 1인 1설명 × 정해진 바퀴 수
   │
   ▼
[토론] 자유 토론 (기본 2분)
   │
   ▼
[투표] 동시에 1명 지목 → 집계
   │
   ├─ 동점 ──▶ [동점 처리] (§8.3)
   │
   ▼
[공개] 최다 득표자의 카드 공개
   │
   ├─ 시민이었다 ─────────────▶ 라이어 승리
   │
   └─ 라이어였다 ─▶ [정답 맞히기] 1회
                       ├─ 맞힘 ──▶ 라이어 승리
                       └─ 틀림 ──▶ 시민 승리
   │
   ▼
[정산] 점수 기록 → 다음 라운드 (선 플레이어 왼쪽으로 이동)
```

| 단계 | 기본 시간 | 비고 |
|---|---|---|
| 역할 확인 | 15초 | |
| 설명 (1인당) | 15 ~ 20초 | 시간 초과 시 §6.6 |
| 토론 | 2분 | 전원 동의 시 조기 종료 가능 |
| 투표 | 10초 (동시 지목) | |
| 최후 변론 (선택) | 30초 | |
| 정답 맞히기 | 15초 | 기회는 **1번** |

## 6. 설명 단계 상세 규칙

### 6.1 기본

- 자기 차례에 제시어에 대한 **설명을 한 번** 한다. 한 마디·한 문장·한 단어 모두 가능(모드에 따라 제한, §14).
- 차례는 시계 방향. 설명 중 다른 사람은 **끼어들 수 없다**(질문·반박은 토론 단계에서).
- 이미 다른 사람이 한 설명을 **그대로 반복할 수 없다**. 같은 뜻을 다른 말로 하는 것은 허용.

### 6.2 금지되는 설명 (반칙)

| 금지 | 예 (제시어: 김치찌개) | 이유 |
|---|---|---|
| 제시어를 직접 말하기 | "김치찌개" | 라이어에게 정답 노출 |
| 제시어의 일부 글자를 말하기 | "김치가 들어가요" ※ | 정답이 거의 노출됨 |
| 글자 수·초성·철자 힌트 | "네 글자", "ㄱㅊㅉㄱ" | 단어 맞히기 게임이 아님 |
| 다른 언어로 그대로 번역 | "Kimchi stew" | 사실상 정답 |
| 몸짓·소리로 정답 흉내 | 끓는 소리 + 김치 써는 동작 | 오프라인 기본 모드에선 말로만 |
| 카드를 보여주기 / 귓속말 | | 정보 격리 위반 |
| "나 시민이야" 식 맹세만 하기 | "저는 진짜 알아요" | 설명이 아님 → 다시 설명해야 함 |

※ "일부 글자" 규칙은 엄격도가 갈린다. **기본 규칙**: 제시어를 구성하는 **단어(어절)** 를 그대로 말하면 반칙. "김치"는 "김치찌개"의 구성 단어이므로 반칙. "발효 음식이 들어가요"는 허용.

### 6.3 허용되는 설명

- 특징, 용도, 장소, 느낌, 연상, 경험담, 비유, 반대말 등 **무엇이든** 제시어를 간접적으로 가리키면 된다.
- 거짓말도 허용된다. 시민이 일부러 엉뚱한 설명을 해서 라이어를 떠보는 것도 전략이다(단, 자기가 의심받는 것은 감수).
- 라이어는 당연히 아는 척 지어내서 말한다.

### 6.4 설명의 "구체성" 가이드

| 수준 | 예 (제시어: 김치찌개) | 평가 |
|---|---|---|
| 너무 모호함 | "먹는 거예요" | 카테고리만 반복 → 라이어처럼 보임 |
| 적당함 | "겨울에 생각나요", "빨개요" | 아는 사람끼리만 통함 |
| 너무 구체적 | "돼지고기 넣고 신 김치로 끓여요" | 라이어가 정답을 알아챔 |

### 6.5 바퀴 수

- **기본 1바퀴**: 빠르고 긴장감 있음. 라이어가 잘 숨는다.
- **2바퀴(권장)**: 두 번째 바퀴에서는 첫 바퀴 설명을 듣고 더 날카롭게 말할 수 있어 시민에게 유리.
- 바퀴 수는 라운드 시작 **전에** 정하고 도중에 바꾸지 않는다.

### 6.6 시간 초과·말 못함

- 제한시간 안에 설명하지 못하면 "**패스**"로 처리되고, 그 사실은 모두에게 보인다(라이어 의심 요소).
- 설명 중 반칙이 나오면 §12 처리.

## 7. 토론 단계

- 모든 설명이 끝나면 **자유 토론**. 누구에게나 질문하고, 답하고, 반박할 수 있다.
- 토론 중에도 §6.2의 금지 사항(제시어·구성 단어 언급 등)은 그대로 적용된다.
- 라이어가 제시어를 이미 눈치챘더라도 **토론 중에 정답을 말하면 안 된다**(말하면 그 자체가 정답 맞히기 사용으로 간주하지 않음 — §13 Q9 참고, 반칙 처리).
- 시간이 끝나거나 **전원이 투표 준비를 외치면** 투표로 넘어간다.
- 선택 규칙 **"한 명씩 해명"**: 토론 대신 1인당 20초씩 순서대로 자기를 변호.

## 8. 투표 단계

### 8.1 투표 방법

- 진행자의 "하나, 둘, 셋!" 신호에 **전원이 동시에** 한 명을 손가락으로 지목한다(또는 비밀 투표 용지).
- **자기 자신은 지목할 수 없다.**
- 기권은 불가. 시간 안에 안 고르면 진행자가 무효표로 처리한다(무효표는 아무도 득표하지 않음).
- 라이어도 투표한다(시민 한 명에게 표를 몰아 그를 희생양으로 만드는 것이 라이어 전략).

### 8.2 집계

- 가장 많은 표를 받은 **1명**이 지목된다. **과반일 필요는 없다**(단순 최다).
- 선택 규칙 **"과반 필요"**: 과반을 못 받으면 아무도 지목되지 않은 것으로 보고 라이어 승리. 하드 모드로 쓴다.

### 8.3 동점 처리 (기본 규칙)

1. 동점자들만 **15초씩 해명**한다.
2. 동점자를 **제외한** 나머지가 동점자 중에서만 **재투표**한다(동점자 본인들은 재투표하지 않음).
3. 재투표도 동점이면 **라이어 승리**(시민이 결론을 못 냈으므로).

다른 선택 규칙(시작 전 합의):

| 방식 | 내용 |
|---|---|
| 동점 = 라이어 승리 | 재투표 없이 즉시 라이어 승리. 빠른 진행용 |
| 동점자 전원 공개 | 동점자 모두 카드 공개. 그중 라이어가 있으면 라이어 정답 맞히기로 진행, 없으면 라이어 승리 |
| 진행자 결정 | 진행자가 있는 오프라인 친목 모임용 |

### 8.4 공개

- 최다 득표자는 카드를 **공개**한다.
- 시민이었다면 → 즉시 **라이어 승리**. 진짜 라이어도 정체를 밝힌다.
- 라이어였다면 → §9 정답 맞히기.

## 9. 라이어의 최후 변론 · 정답 맞히기

### 9.1 최후 변론 (선택 규칙)

공개 **직전**, 최다 득표자에게 30초 변론 기회를 준 뒤 **찬반 투표**(공개할지 말지)를 한 번 더 하는 방식. 반대가 과반이면 공개하지 않고 라이어 승리로 처리한다(마피아식 긴장감을 원할 때). 기본 규칙에서는 사용하지 않는다.

### 9.2 정답 맞히기 (필수)

- 라이어로 드러난 플레이어는 **단 한 번** 제시어를 말할 수 있다. 제한시간 15초.
- 이 시점에 시민들은 아무 힌트도 줄 수 없다(표정 관리 포함 — 오프라인 매너).
- **맞힘** → 라이어 승리. **틀림 / 시간 초과 / 포기** → 시민 승리.

### 9.3 정답 인정 기준

| 경우 | 판정 |
|---|---|
| 정확히 같은 단어 | 정답 |
| 띄어쓰기·맞춤법 차이 ("김치 찌개") | 정답 |
| 널리 쓰이는 동의어·표준 명칭 차이 ("핸드폰" ↔ "휴대폰") | 정답 |
| 외래어 표기 차이 ("케익" ↔ "케이크") | 정답 |
| 상위어 ("찌개") | **오답** |
| 하위어·더 구체적인 것 ("참치김치찌개") | **오답** (기본). 선택 규칙으로 인정 가능 |
| 비슷하지만 다른 것 ("김치찜") | **오답** |
| 답을 여러 개 말함 ("김치찌개 아니면 부대찌개") | **첫 번째만** 인정 |

판정이 애매하면 **시민 전원 다수결**, 그래도 동수면 **라이어에게 유리**하게(정답) 판정한다.

## 10. 승패 판정

| 상황 | 결과 |
|---|---|
| 시민을 지목함 | **라이어 승리** |
| 동점이 끝까지 안 풀림 (기본 규칙) | **라이어 승리** |
| 라이어를 지목, 라이어가 제시어 맞힘 | **라이어 승리** |
| 라이어를 지목, 라이어가 제시어 틀림 | **시민 승리** |
| 시민이 설명 중 제시어를 직접 말함 (중대 반칙) | **라이어 승리** (§12) |
| 라이어가 스스로 정체를 밝힘 | 정답 맞히기로 바로 이동 (§13 Q7) |

- 최고 점수가 우승. 동점이면 **라이어로서 얻은 점수**가 높은 사람, 그래도 같으면 공동 우승.
- 대안: 먼저 **10점**에 도달한 사람이 즉시 우승.

## 12. 반칙과 벌칙

| 반칙 | 처리 |
|---|---|
| **시민**이 제시어(또는 구성 단어)를 말함 | 라운드 즉시 종료, **라이어 승리**(+3). 반칙한 시민 −1 |
| **라이어**가 반칙 설명(초성, 글자 수 등) | 즉시 라이어로 간주 → 정답 맞히기 없이 **시민 승리** |
| 시민이 초성·글자 수 등 금지 힌트 | 경고 1회, 2회째부터 위와 같이 라이어 승리 |
| 카드 보여주기·훔쳐보기 | 그 라운드 무효, 재배부. 고의라면 반칙자 −2 |
| 투표 후 표 바꾸기 | 처음 지목만 유효 |
| 정답 맞히기 중 시민이 힌트 (표정·몸짓 포함) | 라이어 정답으로 처리 |
| 설명 순서 무시, 끼어들기 | 경고. 반복 시 해당 플레이어 다음 설명 패스 |

> 친목 모임에서는 점수 벌칙 대신 "벌칙 미션"으로 바꿔도 된다. 다만 **시민의 제시어 노출 = 라이어 승리**만은 게임 근간이므로 유지한다.

## 13. 특수 상황 판정 (FAQ)

**Q1. 라이어가 설명 중에 우연히 제시어를 정확히 말해버렸다.**
A. 반칙 아님(라이어는 제시어를 모르니까). 시민은 동요하지 말 것 — 표정이 정답을 알려준다. 라이어가 나중에 지목되면 그 단어로 정답 맞히기를 하면 된다.

**Q2. 시민이 첫 번째 설명자인데 너무 불리하다.**
A. 맞다. 선은 정보가 가장 적은 상태로 말해야 한다. 그래서 선은 라운드마다 돌아가며, 선택 규칙 **"선은 라이어가 될 수 없음"** 을 쓸 수도 있다(단, 이 규칙을 쓰면 선은 확정 시민이 되므로 인원이 적을 땐 비권장).

**Q3. 라이어가 첫 번째 설명자다.**
A. 카테고리만 듣고 말해야 하니 가장 어렵다. 카테고리 전체에 두루 맞는 무난한 말("자주 봐요")로 넘기거나, 과감하게 특정 쪽으로 찍는다.

**Q4. 두 시민의 설명이 서로 모순된다.**
A. 정상이다. 한쪽이 라이어일 수도, 둘 다 떠보는 중일 수도 있다. 토론에서 따진다.

**Q5. 제시어를 모르는 단어였다(시민인데).**
A. 역할 확인 직후 진행자에게 조용히 알린다. 진행자는 라운드를 **무효 처리하고 새 제시어로 재배부**한다. 설명이 시작된 뒤에는 무르지 않는다(그냥 라이어처럼 플레이하게 됨 — 그것도 재미).

**Q6. 카테고리 공개를 깜빡했다.**
A. 설명이 시작되기 전이면 공개 후 진행. 시작된 뒤라면 라운드 무효.

**Q7. 라이어가 토론 중 "제가 라이어예요"라고 자백한다.**
A. 허용. 투표 없이 바로 공개 → 정답 맞히기로 간다. (정답을 확신할 때 쓰는 전략.) 시민이 거짓 자백하는 것도 허용되지만, 자백자는 그대로 지목된 것으로 처리되어 시민이면 라이어 승리다.

**Q8. 지목된 사람이 카드 공개를 거부한다.**
A. 공개는 의무. 앱에서는 자동 공개.

**Q9. 라이어가 토론 중에 "혹시 김치찌개?"처럼 정답을 떠본다.**
A. 정답을 직접 말하며 떠보는 것은 금지(시민 반응으로 정답 확인이 가능해짐). 경고 후 반복 시 시민 승리. 간접적으로 떠보는 것("뜨거운 거 맞죠?")은 허용 — 시민은 대답하지 않아도 된다.

**Q10. 투표에서 아무도 라이어를 고르지 않았는데 최다 득표자가 라이어였다?**
A. 불가능한 상황이 아니다 — 최다 득표자가 라이어면 그냥 정답 맞히기로 간다. 개인 보너스(§11.1)는 실제 투표한 시민만 받는다.

**Q11. 라이어가 투표에서 자기 자신을 찍으려 한다.**
A. 자기 지목 불가(§8.1). 앱은 버튼을 막는다.

**Q12. 플레이어가 중간에 나갔다.**
A. 오프라인: 나간 사람이 라이어면 라운드 무효, 시민이면 그 사람 없이 계속. 온라인: §18.6.

**Q13. 3명이면 라이어가 너무 쉽게 잡힌다/안 잡힌다.**
A. 3명은 1표 차이가 결정적이라 운 요소가 크다. §15의 3인 변형(2바퀴 + 정답 맞히기 2회 등)을 쓴다.

**Q14. 설명을 "글자"가 아니라 "그림"으로 해도 되나?**
A. 기본 규칙은 말로만. 그림은 변형 모드(§14.8).

**Q15. 같은 제시어가 다른 라운드에 또 나왔다.**
A. 진행자 실수. 이미 나온 제시어는 목록에서 지운다. 앱은 한 판 안에서 중복을 막는다.

## 14. 변형 규칙 (모드)

라운드 시작 전 하나 이상을 고를 수 있다. 서로 충돌하는 조합은 표에 명시.

### 14.1 바보 모드 (라이어가 자기가 라이어인 줄 모름)

- 라이어는 "라이어" 카드 대신 **같은 카테고리의 다른 제시어**를 받는다. 예: 시민 "김치찌개", 라이어 "된장찌개".
- 라이어는 자기가 시민이라고 믿고 설명한다. 다른 사람 설명이 이상하면 "내가 라이어인가?"를 스스로 깨닫는 재미.
- 정답 맞히기 규칙은 동일(라이어가 진짜 제시어를 맞혀야 함).
- **제시어 짝은 비슷해야 한다**(§17.3).

### 14.2 스파이 모드 (라이어 편 시민)

- 7명 이상 권장. 시민 중 1명이 **스파이**: 제시어를 알고, 라이어를 몰래 돕는다.
- 스파이는 라이어가 누군지 **모른다**(선택: 안다 — 더 강력).
- 라이어 승리 시 스파이도 같이 승리. 스파이가 지목되면 공개되고 **라이어 승리**가 아니라 **재투표**(1회).
- 점수: 스파이는 라이어와 같은 점수를 받는다.

### 14.3 다중 라이어

- 8명 이상: 라이어 **2명**. 라이어끼리도 서로를 모른다.
- 투표로 **2명**을 지목(1인 2표, 같은 사람에게 2표 불가) — 상위 2명 공개.
- 둘 다 잡아야 시민 승리 후보. 잡힌 라이어마다 정답 맞히기 1회, **하나라도 맞히면 라이어팀 승리**.
- 한 명만 잡으면 잡힌 라이어가 정답 맞히기 → 틀려도 남은 라이어가 있으므로 **라이어팀 승리**(기본) / 선택: 무승부.

### 14.4 한 단어 모드

- 설명은 **한 단어(명사·형용사 하나)** 로만. 조사·문장 금지. 빠르고 날카롭다.

### 14.5 질문 모드

- 설명 대신 차례가 된 사람이 **지목한 사람에게 질문**하고, 질문받은 사람이 답한다. 답한 사람이 다음 질문자(같은 사람에게 연속 질문 불가).
- 각자 최소 1번은 답하도록 진행자가 조정.

### 14.6 라이어 정답 맞히기 강화/약화

| 설정 | 효과 |
|---|---|
| 정답 맞히기 2회 | 라이어 유리 (3~4인 권장) |
| 정답 맞히기 없음 | 지목되면 그대로 시민 승리 — 시민 매우 유리, 초보 라이어용 아님 |
| 객관식 정답 맞히기 | 같은 카테고리 단어 **6개 중 하나** 고르기 — 앱에서 흔히 쓰는 방식, 정답 판정 분쟁이 없음 |

### 14.7 카테고리 비공개 (하드)

- 라이어에게도 카테고리를 알려주지 않는다. 시민은 카테고리를 안다. 라이어 매우 불리 → 인원이 많을 때만.

### 14.8 그림 모드

- 설명을 말 대신 **10초 그림**으로. 글자·숫자 쓰기 금지. 온라인 앱 친화적.

### 14.9 침묵 모드

- 토론 단계 없음. 설명 → 바로 투표. 짧은 판을 여러 번 돌릴 때.

## 16. 전략 가이드

### 시민

- **두 번째 바퀴를 노려라**: 첫 바퀴는 모호하게, 두 번째에 동료 시민만 알아들을 디테일.
- **"아는 사람만 아는" 경험담**이 최고의 설명이다. 예: "어제 엄마가 끓여줬어요"는 라이어도 흉내 낼 수 있지만, "쉰 걸로 해야 맛있어요"는 정답을 모르면 못 한다.
- 라이어의 설명은 보통 **앞사람 설명을 살짝 변형**한 것이다. 독창성 없는 설명을 의심하라.
- 라이어가 제시어를 눈치챈 것 같으면 지목해도 질 수 있다 — 너무 구체적인 설명을 자제시켜라.

### 라이어

- 앞사람들의 설명에서 **공통분모**를 찾아 가장 그럴듯한 후보 2~3개로 좁힌다.
- 후보들에 **모두** 맞는 설명을 한다.
- 일부러 한 시민을 의심하는 발언으로 표를 분산시켜라.
- 잡혀도 끝이 아니다. 정답 맞히기를 위해 **토론 내내 후보를 업데이트**한다.

### 스파이(모드)

- 라이어로 보이는 사람에게 **조금 더 구체적인 정보**를 흘린다. 너무 티 나면 같이 잡힌다.

## 17. 카테고리·제시어 작성 규칙과 예시

### 17.1 좋은 제시어의 조건

1. **모두가 아는 단어**: 참가자 연령대 기준으로 누구나 설명 가능해야 한다.
2. **카테고리 안에 비슷한 단어가 많을 것**: 라이어가 추측할 여지가 있어야 재밌다.
3. **고유명사는 신중히**: 연예인·캐릭터 이름은 아는 사람만 알아 불공정할 수 있다. 앱은 **실존 인물·상표 제외** 권장(저작권·초상권 방침).
4. **한 단어 또는 짧은 복합어**: 문장형 제시어 금지.

### 17.2 기본 카테고리 예시 (각 20개)

| 카테고리 | 제시어 |

### 18.1 위치·ID 제안

- 디렉터리: `src/games/liarGame/` (게임 ID `liar-game`), 표시명은 오리지널 이름.

- 통계·업적: `onComplete.self` 전달 + `GAME_SPECS` 항목 추가(프로젝트 공통 규칙).

### 18.2 비밀 정보 처리 (가장 중요)

락스텝 구조에서는 모든 기기가 같은 상태를 계산하므로, **제시어를 상태에 평문으로 두면 라이어 기기에서도 보인다**(개발자 도구로 엿보기 가능). 선택지:

| 방식 | 장점 | 단점 |
|---|---|---|
| A. 방장 권위형: 방장 기기만 제시어 보유, 각 좌석에 개별 메시지로 역할 전송 | 단순, 친구끼리 충분 | 방장은 항상 제시어를 앎 → 방장은 라이어가 될 수 없거나, 방장이 라이어일 때만 방장 화면에서 숨김 처리 |
| B. 서버 함수(Supabase Edge Function)가 역할 배정·정답 판정 | 공정 | 서버 코드 필요 |
| C. 시드 공개형 (모든 기기가 계산) | 구현 최소 | 치팅 가능 — 비권장 |

권장: **B**, 빠른 출시는 **A**(방장도 플레이어로 참여 시 방장 기기는 "제시어 보기" 이외의 경로로 노출 금지 — UI는 숨기되 기술적 치팅은 감수함을 명시).

### 18.3 상태 머신

```
LOBBY → ROLE_REVEAL → DESCRIBE(seat, lap) → DISCUSS → VOTE
      → (TIE_DEFENSE → REVOTE)? → REVEAL → (LIAR_GUESS)? → ROUND_END
      → 다음 라운드 ROLE_REVEAL 또는 GAME_OVER
```

### 18.4 액션

| 액션 | 보내는 쪽 | 내용 |
|---|---|---|
| `START_ROUND` | 방장/서버 | `{ round, category, firstSeat, mode }` (제시어는 포함 안 함) |
| `ROLE_PRIVATE` | 방장/서버 → 각 좌석 | `{ seat, role, word? }` 개별 전송 |
| `SUBMIT_DESCRIPTION` | 차례 플레이어 | `{ seat, lap, text }` — 2~30자, 금칙어 필터(§18.5) |
| `DISCUSS_DONE` | 누구나 | 조기 종료 요청(전원 시 이동) |
| `CAST_VOTE` | 각 플레이어 | `{ voter, target }` — 자기 지목 불가, 1회 |
| `LIAR_GUESS` | 라이어 | `{ text }` 또는 객관식 `{ choice }` |
| `TIMEOUT` | 방장 | 해당 단계 미행동 좌석 목록 → 패스/무효표 |

### 18.5 자동 판정

- **설명 금칙어**: 제시어 및 그 구성 어절, 공백 제거 비교, 초성 문자열(`ㄱ-ㅎ`만으로 이루어진 2자 이상)을 서버/방장이 차단 → "제시어가 포함돼 있어요" 안내 후 재입력. 차단은 반칙 처리 대신 **입력 거부**로 해서 사고를 막는다.
- **정답 판정**: 공백·대소문자 제거 후 비교 + 카테고리별 동의어 표. 애매한 판정 분쟁을 없애려면 **객관식(§14.6) 기본** 권장.
- 집계·동점 처리는 §8과 동일하게 엔진에서 결정적으로 계산.

### 18.6 이탈·재접속

- 프로젝트 공통 **투표 기반 봇 대체** 적용. 봇 설명은 카테고리/제시어 기반 미리 준비된 힌트 문장 풀에서 선택, 라이어 봇은 카테고리 공통 문장 사용.
- 라이어가 이탈하고 봇 대체를 거부하면 라운드 무효(점수 없음).

### 18.7 화면 구성 요약

- 상단: 카테고리, 라운드/점수, 단계 타이머.
- 중앙: 좌석 원형 배치 + 각 좌석 설명 말풍선 기록(바퀴별).
- 하단: 내 역할 카드(길게 눌러 보기 — 옆 사람 훔쳐보기 방지), 입력창/투표 버튼.
- 공개 연출: 득표 막대 → 카드 뒤집기 → (라이어면) 정답 맞히기 → 정답 공개.
